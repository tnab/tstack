# Document

Deliver a document suited to its audience and purpose.

1. Establish the document's purpose, reader, requested format, and source boundaries. Preserve the user's template or existing voice where appropriate. For edits, inspect the supplied revision before changing it.
2. Use [brief](../../brief/SKILL.md) to synthesize a substantial source packet, or [search](../../search/SKILL.md) for material gaps when broader research is permitted. Reuse existing evidence; do not research a pure wording edit.
3. Draft with [write](../../write/SKILL.md). Make the main answer or requested decision easy to find. If a choice is the document's purpose, use [decide](../../decide/SKILL.md) for the reasoning before drafting it.
4. Use [review](../../review/SKILL.md) when factual, numerical, or practical claims warrant it. Resolve supported findings, keep consequential uncertainty, and finish the prose through write after substantive revisions.
5. For a requested file, use available format-specific capabilities to create it and inspect the saved artifact. Check readability, tables, links, and pagination where applicable. State any rendering limitation instead of claiming visual verification.

Done when the requested document exists, its central claims are supported, and the delivered revision has been checked. Drafting does not authorize publishing or changing a shared document unless the request includes that action.

# Knowledge Stack entry workflow checks

Version: `0.3.0-alpha.1`. Scope: the new `kstack` entry skill, playbooks, and portable authoring/evaluation workflows. These are synthetic execution checks, not a comparison against another version or an unassisted baseline.

## Method

Five fresh worker contexts received the entry skill, an ordinary task request, and the necessary fictional source files. Expected checks and prior results were withheld from their permitted workspaces. Four tasks used read-only source packets; the authoring task could change only a disposable package copy. The coordinator inspected the returned text and saved artifacts against the source records.

The authored handover skill then received a separate fresh-context run on both supplied shift-note examples. Its generated files were used only for this exercise and are not part of the released skill set.

## Observed results

| Request | Observed output checks |
|---|---|
| Meeting preparation | Produced a pre-read and a 20-minute agenda. Preserved the approved conditional October 1 plan, the unapproved October 8 proposal, the blocked review, and the September 18 cutoff. |
| Wording edit | Returned one shortened paragraph with the dates, source markers, conditions, sample counts, and sampling limitation intact. No extra report was included. |
| Source-bound document | Produced a sourced replacement memo under 220 words. Corrected 12/40 to 30%, distinguished a 30-percentage-point increase from 50% relative growth, preserved the lack of causal evidence, and excluded the later approval. |
| Custom workflow | Produced three source-grounded sorting cards, a facilitator key, and a draft note. Kept approval, proposal, and commitment distinct. Automatic approval review blocked saving the response file; the complete text was returned and inspected instead. |
| Skill authoring and evaluation | Created a portable handover skill, routing, a playbook, and two cases in the disposable copy. The copy passed structural validation. The author reported a worker-capacity limit accurately; the coordinator then ran a separate fresh worker. Its two handoffs preserved the conditional offer, missing reminder owner, blocked review, and absence of a completion deadline. |

These outputs met the material evidence and scope checks inspected. Exact file-read routing was not independently audited for every worker, so these results do not establish compliance with every internal step. The document draft could also distinguish the offered checklist review from accepted ownership more explicitly; it did not falsely assign the declined writing task.

## Structural and public-content review

- The repository validator passed for four manifests, eleven skill headers, twelve reachable playbooks, local links, and twelve case definitions.
- The skill and plugin format validators passed. Missing-link, unreachable-playbook, and malformed-case probes were rejected as expected.
- A separate read-only review found no consequential defects in routing, recursive handoffs, naming, attribution, or authorization boundaries.
- Working-tree inspection and targeted searches found no private paths, private project context, or credential patterns. This is limited review evidence, not exhaustive secret detection. Raw worker artifacts containing temporary paths were not published.

## Client and coverage limits

A Cursor CLI smoke test was attempted using a synthetic paragraph and local project skills. Execution stopped with an authentication error, so Cursor runtime behavior remains unverified. This run did not verify marketplace installation, automatic discovery across clients, live connectors, document rendering, or presentation generation.

The checks invoked `kstack` explicitly. They do not establish automatic skill selection, behavior across later conversation turns, general reliability, or a quality advantage over other workflows. The seven earlier component cases remain available; their historical results are separate from this entry-workflow run.
